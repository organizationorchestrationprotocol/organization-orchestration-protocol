# Maintainer reference mechanisms

These are local producer fixtures, not an installable OOP distribution, consumer prerequisites or proof of live runtime governance. `PROMPT.md` is the only normative source. JSON Schema describes the intended producer contract; the reference engine demonstrates closure, assembly, three-valued guards, selective invalidation, scoped reuse and readiness distinctions. No effects, provider calls, credential enrollment, model calls, installation or repository audit are performed.

Run `node maintainer/export-candidate.mjs`, then `node --test maintainer/reference-engine.test.mjs` for isolated positive/negative/unknown scenarios. Run `node maintainer/benchmark.mjs` for reproducible fixture measurements. These commands belong exclusively to maintenance; do not place them in consumer activation, bootstrap, migration or recovery. Node is a maintainer implementation choice, not a consumer dependency.

Run `node maintainer/record-evidence.mjs` to rerun the isolated checks and record their exact subjects, canonical retained-text comparison and semantic change dispositions. This comparison uses the local prior commit, not a verified release regression baseline; it intentionally rejects unrelated canonical edits. Stored evidence describes only the recorded subjects and must be regenerated when those subjects change.

The fixture catalog and single exported BOOT-11 contract are deliberately incomplete and cannot satisfy REL-02/REL-11. They are not substituted for canonical modules. The restricted schema-profile validator supports only this profile's declared keywords and rejects unsupported features; it is not a general JSON Schema implementation. Its test result applies only to the checked candidate contract. Local test outcomes do not establish complete semantic reading/coverage, installed runtime controls, provider access, cross-runtime compatibility, latest-prior verified regression, publication or consumer adoption. Candidate generation and live adapters require separate complete source-to-derived semantic review and actual integration evidence before distribution readiness.

Benchmark byte counts describe fixture governing content only. Engine duration is measured locally; token counts, model calls, end-to-end latency and money are not measured. No savings are inferred. A future ready distribution uses `dist/entry.json`; the existing official entry must not be changed to a candidate.
